INTRODUCTION                                                          *pantry*

pantry.nvim is a bundle of small Neovim jars. Each jar is off until you
turn it on. pantry.nvim needs Neovim 0.12 or newer.

                                                              *pantry.setup()*
pantry.setup({config})
    Turns on each jar named in {config}. The value for each name is the
    options table for that jar. A jar with `enabled = false` stays off.
    pantry never loads a jar that {config} does not name.
>lua
    require("pantry").setup({
      rsi = {},
      linelimit = {},
    })
<
Each jar also has its own setup function, for example
`require("pantry.rsi").setup({})`.

Run `:checkhealth pantry` to see which jars are on.

RSI                                                               *pantry-rsi*

pantry.rsi adds readline editing keys to insert mode and the command line.
These are the keys that shells such as bash use.

Key            Insert mode                      Command line ~
<C-a>          first non-blank character        start
<C-e>          end of line                      Neovim's own
<C-b>          left one character               left one character
<C-f>          right one character              right one character
<C-d>          delete character                 delete character
<C-k>          kill to end of line              kill to end
<C-u>          kill to first non-blank          kill to start
<C-w>          kill back to previous space      kill back to previous space
<M-p>          kill back one path segment       kill back one path segment
<C-t>          Neovim's own                     swap characters
<C-y>          Neovim's own                     paste latest kill
<M-y>                                           after <C-y>: older kill
<M-b>          back one word                    back one word
<M-f>          forward one word                 forward one word
<M-d>          kill next word                   kill next word
<M-BS>         kill previous word               kill previous word
<M-C-h>        kill previous word               kill previous word
<M-u>          uppercase next word              uppercase next word
<M-l>          lowercase next word              lowercase next word
<M-c>          capitalize next word             capitalize next word
<M-.>                                           last argument of an
                                                earlier command

At the end of a line these keys keep Neovim's own meaning:
- <C-d> removes one indent level in insert mode and lists completions on
  the command line.
- <C-f> keeps Neovim's insert-mode meaning and opens the command-line
  window on the command line.
- Insert-mode <C-e> inserts the character below the cursor.
On a search line (`/` or `?`), <C-t> keeps Neovim's meaning.

                                                         *pantry-rsi-killring*
A kill deletes text and saves it in the kill ring. Kills do not change any
register. <C-y> pastes the latest kill on the command line. Pressing <M-y>
right after <C-y> replaces the pasted text with the next older kill.
Pressing <M-.> again replaces the inserted argument with the last argument
of the command before it.

Insert-mode keys stay inside insert mode, so |.| repeats the whole insert and
one |u| undoes it.

While a completion menu is open, <C-e>, <C-k> and <C-y> go to the menu.
pantry checks blink.cmp when it is loaded. Otherwise it checks Neovim's
built-in popup menu.

                                                          *pantry-rsi-options*
keys
    A table of keys to turn off. Set a key to `false` to keep Neovim's own
    meaning for it in both modes.
>lua
    require("pantry").setup({
      rsi = {
        keys = { ["<C-k>"] = false },
      },
    })
<

LINELIMIT                                                   *pantry-linelimit*

pantry.linelimit shows how close each line is to a line length limit.

- A faint `│` appears just after the limit on lines that are within `near`
  columns of it. Shorter lines get nothing.
- A line that goes past the limit gets `+N` after its end. N is how many
  columns it is over.
- Text past the limit keeps its normal color.

pantry checks only the lines on the screen. It counts width in screen
columns, so a tab or a wide character counts as wide as it looks. Concealed
text still counts.

                                                      *pantry-linelimit-limit*
The limit for a window comes from the first of these that is set:
1. The window's 'colorcolumn'. pantry uses the first entry. `+1` means the
   limit is 'textwidth', and `81` means the limit is 80.
2. 'textwidth', when it is above 0.
3. `max_line_length` from an EditorConfig file.
4. The `filetypes` option.
If none of these is set, the window shows nothing.

While the jar is on, pantry hides Neovim's own 'colorcolumn' stripe in
the windows it checks. It still uses the 'colorcolumn' value as the limit.
|pantry.linelimit.disable()| puts the stripe back.

pantry skips floating windows, buffers that have a 'buftype' such as help or
terminal buffers, and the filetypes in `skip`.

                                                    *pantry-linelimit-options*
near
    How many columns before the limit a line starts to get the mark.
    Default: `10`.

filetypes
    A limit for each filetype, such as `{ lua = 120 }`. Default: `{}`.

skip
    Filetypes to leave alone.
    Default: `{ "help", "qf", "man", "terminal", "prompt" }`.

enabled
    Set to `false` to keep the jar off. Default: `true`.
>lua
    require("pantry").setup({
      linelimit = {
        near = 5,
        filetypes = { lua = 120, markdown = 80 },
      },
    })
<
                                                 *pantry-linelimit-highlights*
PantryLineLimit       The mark. Links to |hl-NonText|.
PantryLineLimitOver   The `+N` count. Links to `DiagnosticVirtualTextWarn`.
A colorscheme can set its own colors for both.

                                                 *pantry.linelimit.enable()*
                                                *pantry.linelimit.disable()*
pantry.linelimit.enable()
pantry.linelimit.disable()
    Turn the jar on or off. `setup` calls `enable()` unless `enabled` is
    `false`.

JUMPS                                                           *pantry-jumps*

pantry.jumps adds keys that move the cursor by the structure of the code. It
reads the structure from Neovim's built-in |treesitter|, so a language needs
a tree-sitter parser for the code keys to work.

Keys        Modes                Moves to ~
{  }        normal               one block level out or in
]j [j       normal, visual, op   next or previous node at the same level
]r [r       normal, visual, op   next or previous return
]n [n       normal               next or previous merge-conflict marker
]E [E       normal               next or previous diagnostic error
]W [W       normal               next or previous diagnostic warning
]f [f       normal               next or previous file in the folder
]P [P       normal, visual, op   next or previous paragraph, like } and {

Every key takes a count. A jump from normal mode goes into the |jumplist|,
so |CTRL-O| goes back. The markdown keys ]` [` ]x and [x moved to the
markdown jar.

                                                     *pantry-jumps-levels*
{ goes to the first line of the block around the cursor. 2{ goes out two
levels. } goes back down the levels that { came out of. After any other
cursor move or an edit, } goes to the first block inside the block under the
cursor. In a buffer with no parser, { and } keep their paragraph motion.
Visual and operator-pending { and } always keep it.

pantry takes the list of blocks from nvim-treesitter-context when it is
installed. Without it, pantry has its own list for Lua, Python, JavaScript,
TypeScript, Go, Rust, Swift, Bash, JSON, YAML, TOML and markdown.

                                                     *pantry-jumps-siblings*
]j and [j skip over anything nested and stop at the ends of the block. In
JSON, YAML and TOML they move between keys at one level and between the
items of a list.

                                                     *pantry-jumps-returns*
]r and [r use the @return.outer captures from nvim-treesitter-textobjects.
pantry adds its own captures for three languages:
- Rust: the last expression of a function body when it has no semicolon.
- Swift: a return, and the single expression body of a function that
  declares a return type. Closures are skipped.
- Bash: a return, and an echo or printf that is the last command of a
  function, unless it writes to stderr with >&2.

pantry also makes Swift let and var declarations into @assignment text
objects, so textobjects keys such as ]v work on them.

]n and [n stop on lines that start with <<<<<<<, |||||||, ======= or
>>>>>>>.

                                                     *pantry-jumps-options*
keys
    A table of keys to turn off. Set a key to `false` to keep Neovim's own
    meaning for it.
>lua
    require("pantry").setup({
      jumps = {
        keys = { ["]r"] = false },
      },
    })
<

FOCUS                                                           *pantry-focus*

pantry.focus dims every line outside the code around the cursor. While focus
is on, two keys show more or less of the code. The jar is off until you turn
it on.

Each level lights one |treesitter| node and dims the rest. Level 0 is the
line under the cursor, such as a `key: value` pair in JSON. Each level up
lights the next node that covers more lines. A node that covers the same
lines as the one below it is skipped, so every key press changes what you
see. The last level is the whole buffer.

When focus turns on, it lights the first block around the cursor that spans
more than one line. The level stays the same as the cursor moves, and the
lit lines follow the cursor. In a buffer with no parser, level 0 lights the
paragraph under the cursor and level 1 lights the whole buffer.

Key       Mode     Action ~
<M-o>     normal   show more, one level out
<M-i>     normal   show less, one level in

The keys exist only while focus is on, in the buffers you visit while it is
on. The jar has no key to turn it on. Map |pantry.focus.toggle()| yourself:
>lua
    vim.keymap.set("n", "<leader>uf", require("pantry.focus").toggle)
<
Floating windows and buffers that have a 'buftype' are never dimmed.

                                                  *pantry.focus.enable()*
                                                 *pantry.focus.disable()*
                                                  *pantry.focus.toggle()*
                                                   *pantry.focus.widen()*
                                                  *pantry.focus.narrow()*
pantry.focus.enable()
pantry.focus.disable()
pantry.focus.toggle()
    Turn focus on, off, or to the other state.
pantry.focus.widen()
pantry.focus.narrow()
    Light one level more or one level less. They do nothing while focus is
    off.

                                                     *pantry-focus-options*
keys
    A table of keys to turn off. Set a key to `false` to leave it unmapped.

enabled
    Set to `true` to turn focus on at startup. Default: `false`.
    With `focus = {}`, |:checkhealth| reports the jar as set up and off.
>lua
    require("pantry").setup({
      focus = {
        keys = { ["<M-i>"] = false },
      },
    })
<
                                                  *pantry-focus-highlights*
PantryFocusDim   The dimmed lines. Links to |hl-Comment|.
A colorscheme can set its own color for it.

MARKDOWN                                                     *pantry-markdown*

pantry.markdown adds keys to markdown buffers. One key turns a line into a
task and checks or opens it. The other keys move between checkboxes and code
blocks. The jump keys need the markdown tree-sitter parser.

Keys        Modes                Action ~
<C-CR>      normal, insert       toggle the task on the current line
]x [x       normal, visual, op   next or previous checkbox
]` [`       normal, visual, op   next or previous fenced code block

The keys exist only in markdown buffers.

                                                 *pantry-markdown-tasks*
<C-CR> changes the current line by what it holds:
- A plain line becomes `- [ ] line`. The indent stays.
- A list item that starts with `- `, `* `, `+ `, `1. ` or `1) ` gets a
  `[ ] ` box.
- A task with `[ ]` becomes `[x]`.
- A task with `[x]` or `[X]` becomes `[ ]`.
The cursor stays on the same character of the text, in normal and insert
mode.

                                                 *pantry-markdown-jumps*
]x and [x stop on each checkbox, checked or not, and skip text inside code
blocks. ]` and [` stop on the first line of each fenced code block. Every
jump key takes a count. A jump from normal mode goes into the |jumplist|, so
|CTRL-O| goes back.

These four keys used to be part of |pantry-jumps|. They moved here with the
`keys` option that turns them off, so set them in `markdown`, not in `jumps`.

                                                 *pantry-markdown-options*
keys
    A table of keys to turn off. Set a key to `false` to keep Neovim's own
    meaning for it.
>lua
    require("pantry").setup({
      markdown = {
        keys = { ["<C-CR>"] = false },
      },
    })
<

MESSAGES                                                     *pantry-messages*

pantry.messages turns on Neovim's ui2 message window and adds a key that
lists every message since startup. The jar is off until you turn it on.

At setup the jar runs `require("vim._core.ui2").enable()` with
`{ msg = { target = "msg" } }`. ui2 then shows every message, notifications
included, in the message window.

ui2 is private Neovim API, and a Neovim release can change or remove it. The
jar reads each message from ui2's `msg_show` handler to record its time,
level and kind. When that handler is missing, the jar records nothing and
every message still shows. The history then lists the lines of |:messages|
with no time and no kind.

Key          Mode     Action ~
<leader>nh   normal   show the message history, newest first

The snacks view opens a snacks.nvim picker laid out like the snacks
notifications picker. The buffer view opens a read-only buffer in a split,
one line per message with its time, level and kind. A message of several
lines continues on indented lines. `q` closes the buffer. The level is
`error` for errors, `warn` for warnings and `info` for every other message.

                                                  *pantry-messages-options*
ui2
    Set to `false` to leave ui2 alone. Set to a table to pass it to ui2 as
    its options. Default: `true`.

view
    `"snacks"`, `"buffer"`, or `"auto"`. `"auto"` uses snacks when it loads
    and the buffer view otherwise. Default: `"auto"`.

keys
    Maps each key to an action. Set a key to `false` to leave it unmapped.
    Default: `{ ["<leader>nh"] = "history" }`.
    The actions are `"history"`, which uses `view`, `"history_buffer"` and
    `"history_snacks"`.
>lua
    require("pantry").setup({
      messages = {
        view = "buffer",
        keys = { ["<leader>sm"] = "history_snacks" },
      },
    })
<

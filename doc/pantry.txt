INTRODUCTION                                                          *pantry*

pantry.nvim is a set of small Neovim modules in one plugin. Each module is
off until you turn it on. pantry.nvim needs Neovim 0.12 or newer.

                                                              *pantry.setup()*
pantry.setup({config})
    Turns on each module named in {config}. The value for each name is the
    options table for that module. A module with `enabled = false` stays
    off. pantry never loads a module that {config} does not name.
>lua
    require("pantry").setup({
      rsi = {},
      linelimit = {},
    })
<
Each module also has its own setup function, for example
`require("pantry.rsi").setup({})`.

Run `:checkhealth pantry` to see which modules are on.

RSI                                                               *pantry-rsi*

pantry.rsi adds readline editing keys to insert mode and the command line.
These are the keys that shells such as bash use.

Key            Insert mode                      Command line ~
<C-a>          first non-blank character        start
<C-e>          end of line                      Neovim's own
<C-b>          left one character               left one character
<C-f>          right one character              right one character
<C-d>          delete character                 delete character
<C-k>          kill to end of line              kill to end
<C-u>          kill to first non-blank          kill to start
<C-w>          kill back to previous space      kill back to previous space
<M-p>          kill back one path segment       kill back one path segment
<C-t>          Neovim's own                     swap characters
<C-y>          Neovim's own                     paste latest kill
<M-y>                                           after <C-y>: older kill
<M-b>          back one word                    back one word
<M-f>          forward one word                 forward one word
<M-d>          kill next word                   kill next word
<M-BS>         kill previous word               kill previous word
<M-C-h>        kill previous word               kill previous word
<M-u>          uppercase next word              uppercase next word
<M-l>          lowercase next word              lowercase next word
<M-c>          capitalize next word             capitalize next word
<M-.>                                           last argument of an
                                                earlier command

At the end of a line these keys keep Neovim's own meaning:
- <C-d> removes one indent level in insert mode and lists completions on
  the command line.
- <C-f> keeps Neovim's insert-mode meaning and opens the command-line
  window on the command line.
- Insert-mode <C-e> inserts the character below the cursor.
On a search line (`/` or `?`), <C-t> keeps Neovim's meaning.

                                                         *pantry-rsi-killring*
A kill deletes text and saves it in the kill ring. Kills do not change any
register. <C-y> pastes the latest kill on the command line. Pressing <M-y>
right after <C-y> replaces the pasted text with the next older kill.
Pressing <M-.> again replaces the inserted argument with the last argument
of the command before it.

Insert-mode keys stay inside insert mode, so |.| repeats the whole insert and
one |u| undoes it.

While a completion menu is open, <C-e>, <C-k> and <C-y> go to the menu.
pantry checks blink.cmp when it is loaded. Otherwise it checks Neovim's
built-in popup menu.

                                                          *pantry-rsi-options*
keys
    A table of keys to turn off. Set a key to `false` to keep Neovim's own
    meaning for it in both modes.
>lua
    require("pantry").setup({
      rsi = {
        keys = { ["<C-k>"] = false },
      },
    })
<

LINELIMIT                                                   *pantry-linelimit*

pantry.linelimit shows how close each line is to a line length limit.

- A faint `│` appears just after the limit on lines that are within `near`
  columns of it. Shorter lines get nothing.
- A line that goes past the limit gets `+N` after its end. N is how many
  columns it is over.
- Text past the limit keeps its normal color.

pantry checks only the lines on the screen. It counts width in screen
columns, so a tab or a wide character counts as wide as it looks. Concealed
text still counts.

                                                      *pantry-linelimit-limit*
The limit for a window comes from the first of these that is set:
1. The window's 'colorcolumn'. pantry uses the first entry. `+1` means the
   limit is 'textwidth', and `81` means the limit is 80.
2. 'textwidth', when it is above 0.
3. `max_line_length` from an EditorConfig file.
4. The `filetypes` option.
If none of these is set, the window shows nothing.

While the module is on, pantry hides Neovim's own 'colorcolumn' stripe in
the windows it checks. It still uses the 'colorcolumn' value as the limit.
|pantry.linelimit.disable()| puts the stripe back.

pantry skips floating windows, buffers that have a 'buftype' such as help or
terminal buffers, and the filetypes in `skip`.

                                                    *pantry-linelimit-options*
near
    How many columns before the limit a line starts to get the mark.
    Default: `10`.

filetypes
    A limit for each filetype, such as `{ lua = 120 }`. Default: `{}`.

skip
    Filetypes to leave alone.
    Default: `{ "help", "qf", "man", "terminal", "prompt" }`.

enabled
    Set to `false` to keep the module off. Default: `true`.
>lua
    require("pantry").setup({
      linelimit = {
        near = 5,
        filetypes = { lua = 120, markdown = 80 },
      },
    })
<
                                                 *pantry-linelimit-highlights*
PantryLineLimit       The mark. Links to |hl-NonText|.
PantryLineLimitOver   The `+N` count. Links to `DiagnosticVirtualTextWarn`.
A colorscheme can set its own colors for both.

                                                 *pantry.linelimit.enable()*
                                                *pantry.linelimit.disable()*
pantry.linelimit.enable()
pantry.linelimit.disable()
    Turn the module on or off. `setup` calls `enable()` unless `enabled` is
    `false`.

JUMPS                                                           *pantry-jumps*

pantry.jumps adds keys that move the cursor by the structure of the code. It
reads the structure from Neovim's built-in |treesitter|, so a language needs
a tree-sitter parser for the code keys to work.

Keys        Modes                Moves to ~
{  }        normal               one block level out or in
]j [j       normal, visual, op   next or previous node at the same level
]r [r       normal, visual, op   next or previous return
]n [n       normal               next or previous merge-conflict marker
]` [`       markdown only        next or previous fenced code block
]x [x       markdown only        next or previous checkbox

Every key takes a count. Every jump goes into the |jumplist|, so |CTRL-O|
goes back.

                                                     *pantry-jumps-levels*
{ goes to the first line of the block around the cursor. 2{ goes out two
levels. } goes back down the levels that { came out of. After any other
cursor move or an edit, } goes to the first block inside the block under the
cursor. In a buffer with no parser, { and } keep their paragraph motion.
Visual and operator-pending { and } always keep it.

pantry takes the list of blocks from nvim-treesitter-context when it is
installed. Without it, pantry has its own list for Lua, Python, JavaScript,
TypeScript, Go, Rust, Swift, Bash, JSON, YAML, TOML and markdown.

                                                     *pantry-jumps-siblings*
]j and [j skip over anything nested and stop at the ends of the block. In
JSON, YAML and TOML they move between keys at one level and between the
items of a list.

                                                     *pantry-jumps-returns*
]r and [r use the @return.outer captures from nvim-treesitter-textobjects.
pantry adds its own captures for three languages:
- Rust: the last expression of a function body when it has no semicolon.
- Swift: a return, and the single expression body of a function that
  declares a return type. Closures are skipped.
- Bash: a return, and an echo or printf that is the last command of a
  function, unless it writes to stderr with >&2.

pantry also makes Swift let and var declarations into @assignment text
objects, so textobjects keys such as ]v work on them.

]n and [n stop on lines that start with <<<<<<<, ======= or >>>>>>>.

                                                     *pantry-jumps-options*
keys
    A table of keys to turn off. Set a key to `false` to keep Neovim's own
    meaning for it.
>lua
    require("pantry").setup({
      jumps = {
        keys = { ["]r"] = false },
      },
    })
<
